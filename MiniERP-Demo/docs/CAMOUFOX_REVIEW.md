# Έλεγχος Camoufox για λήψη PDF — 22/10/2026

## Απόφαση

Κατάλληλο για προαιρετική, πιλοτική ανάκτηση αρχικών PDF παρόχων. Δεν είναι
άμεση αντικατάσταση του Chromium και δεν ενσωματώθηκε στο runtime με αυτόν τον
έλεγχο. Δεν τεκμηριώνεται βελτίωση επιτυχίας Cloudflare χωρίς δοκιμή στους
συγκεκριμένους παρόχους. Δεν επηρεάζει REST ΑΑΔΕ, λογιστική προετοιμασία ή EBS.

## Τεκμήρια

- Εξετάστηκε το συνημμένο camoufox-main.zip, SHA-256:
  `552da855b032cd4432cd254e683d51b05c06a5df3f7ef33440d81a11cb5e9ad0`.
- Το `python/pyproject.toml` δηλώνει 0.5.7, Python ^3.10 και Playwright <1.63.
  Το Mini ERP έχει Playwright 1.62.0, άρα το δηλωμένο όριο συμφωνεί· αυτό δεν
  αποδεικνύει πλήρη λειτουργική συμβατότητα. Οι περισσότερες πρόσθετες εξαρτήσεις
  του Camoufox δεν είναι pinned.
- Η PyPI έδινε 0.5.8 κατά τον έλεγχο. Το ZIP είναι snapshot main, δεν περιέχει
  αποδεικτικό Git commit και δεν πρέπει να αντιμετωπιστεί ως ελεγμένη release.
- Ο κώδικας launcher υποστηρίζει Windows x86_64/i686. Δεν δηλώνει native Windows
  ARM64 στον πίνακα λειτουργικών/αρχιτεκτονικών.
- GitHub latest release: `v156.0.1-beta.36`, δημοσίευση 2026-10-06.
  Το Windows x86_64 asset δηλώνει **1.311.638.126 bytes**, περίπου 1,22 GiB,
  πριν την αποσυμπίεση. Δεν το κατεβάσαμε ούτε το συμπεριλάβαμε στο Mini ERP.
- Το `browser-pin.json` του συνημμένου είναι κενό. Χρειάζεται συγκεκριμένο,
  δοκιμασμένο ζεύγος Python package/browser και επιβεβαιωμένο hash εγκατάστασης.
- Άδειες: root MPL-2.0, Python wrapper MIT. Η χρήση είναι εφικτή με τήρηση των
  αντίστοιχων notices/υποχρεώσεων και των αδειών επιμέρους εξαρτήσεων. Δεν είναι
  ολόκληρο το browser MIT. Προτιμάται επίσημη ξεχωριστή εγκατάσταση αντί vendoring.

## Σημεία σύνδεσης

Τα `browser_downloads.py` και `browser_recovery.py` ανοίγουν Chromium και
επιστρέφουν Playwright context/page. Το `AsyncCamoufox` μπορεί να παρέχει τα
αντίστοιχα αντικείμενα Firefox, αλλά χρειάζεται χωριστή υλοποίηση εκκίνησης,
κλεισίματος και επίμονου προφίλ. Δεν μεταφέρονται Chromium launch flags/profiles.

Το `print_fallback.py` χρησιμοποιεί `page.pdf()`. Ο εγκατεστημένος Playwright
δηλώνει ρητά ότι παραγωγή PDF υποστηρίζεται μόνο σε headless Chromium. Επομένως
αυτό το σκέλος πρέπει να παραμείνει Chromium. Δεν αρκεί αλλαγή ενός import.

Αν υλοποιηθεί πιλοτικά:

1. Ρητή επιλογή «Ανάκτηση με Camoufox» μόνο για εκκρεμή PDF, με σαφή ένδειξη
   μεγέθους εγκατάστασης και ελεγχόμενες εκδόσεις. Καμία υποχρεωτική εγκατάσταση.
2. Ορατό παράθυρο για σύνδεση/CAPTCHA από τον χρήστη. Καμία υπόσχεση αυτόματης
   παράκαμψης ή μεταβολή της σημερινής χειροκίνητης δυνατότητας.
3. Χωριστό profile ανά εταιρεία/περιβάλλον/browser. Ποτέ προσωπικό profile ή
   credentials ΑΑΔΕ σε ιστοσελίδες παρόχων. Δεν απαιτούνται proxies/GeoIP.
4. Ίδια αντιστοίχιση MARK/ΑΦΜ/ημερομηνίας/αριθμού, έλεγχος πραγματικού PDF,
   hash, εταιρική απομόνωση και audit. Ίδια σαφής διάκριση πρωτότυπου/εκτύπωσης.
5. Δοκιμές λήψης response/download/popup, persistent session, ακύρωσης και
   κλεισίματος, καθώς και διατήρησης Chromium printing και παλιών λειτουργιών.
   Έπειτα μικρή δοκιμή Windows σε συγκεκριμένους παρόχους πριν γίνει προεπιλογή.

## Τι ελέγχθηκε

Εξέταση README, αδειών, packaging, sync/async launch API, version/browser
selection, λήψεων και περιορισμών του υπάρχοντος Mini ERP. Συντακτικός έλεγχος
με AST σε 25 Python modules του launcher, χωρίς εκτέλεση του συνημμένου κώδικα.
Ανάγνωση δημόσιων metadata από PyPI και GitHub για έκδοση/Windows asset.
Δεν έγινε browser launch, δοκιμή Windows ή μέτρηση επιτυχίας πραγματικού παρόχου.
Δεν άλλαξε εφαρμογή, βάση, δεδομένα, credentials ή έτοιμο ZIP.

Πηγές: τοπικό συνημμένο (`python/README.md`, `python/pyproject.toml`,
`python/src/camoufox/{async_api,sync_api,pkgman}.py`, `LICENSE`, `python/LICENSE`),
https://pypi.org/pypi/camoufox/json και
https://api.github.com/repos/daijro/camoufox/releases/latest.


## Επαναξιολόγηση με υπάρχοντα εργαλεία — 23/10/2026

Εκτελέστηκε το `scripts/verify_delivery.py` (υπάρχων ECC-inspired delivery gate),
με συντακτικούς/στοχευμένους στατικούς ελέγχους, πραγματικό unittest runner,
GUI σε Xvfb, Chromium σε συνθετικές σελίδες, συσκευασία, αποσυμπίεση και επανάληψη.
Επιτυχία: 75 backend/tool tests και 16 GUI tests τόσο στο source όσο και στο ZIP,
μαζί με launcher Python, GUI smoke και έλεγχο ανάγνωσης βάσης.
Το αποτέλεσμα αφορά τη σημερινή εφαρμογή **χωρίς Camoufox**. Δεν αποδεικνύει
ότι η μελλοντική ενσωμάτωσή του δεν θα έχει παλινδρομήσεις.

Ελέγχθηκαν έξι διαθέσιμα προηγούμενα ZIP με αναφορές PASSED: Startup-Fix,
PDF-RPA, Connected-Workflow, Expenses-Only, Checked-Demo και AADE-PDF.
Και στα έξι το SHA-256 συμφωνεί με την αντίστοιχη αναφορά. Τα 81 αρχεία
Python/SQL του τελευταίου AADE-PDF ZIP συμφωνούν byte-for-byte με το checkout.
Στη σειρά Startup-Fix → PDF-RPA → Connected-Workflow → Expenses-Only → AADE-PDF
δεν βρέθηκε αφαίρεση αρχείου εφαρμογής/migration. Αυτό είναι σύγκριση αρχείων,
όχι απόδειξη διατήρησης κάθε συμπεριφοράς· οι λειτουργικές εγγυήσεις προέρχονται
από τα αντίστοιχα tests.

Τα tests καλύπτουν άνοιγμα/προεπισκόπηση PDF, δυναμικό embedded PDF με Chromium,
εκτύπωση HTML και απόρριψη challenge ως τιμολογίου, αντιστοίχιση ΑΑΔΕ στην ίδια
εγγραφή Excel, credentials εκτός βάσης, αναβάθμιση παλιάς βάσης με διατήρηση
εγκρίσεων/PDF/ιστορικού, αποκλεισμό ομάδας 2 από RPA και αποφυγή επανάληψης
αποθηκευμένης εγγραφής. Δεν εκτελέστηκε πραγματικό Windows/EBS/AADE.

Πρόσθετα ευρήματα από ανάγνωση κώδικα:

- Το Camoufox `verify_sha256` προειδοποιεί αλλά συνεχίζει όταν λείπει digest.
  Η δική μας εγκατάσταση πρέπει να απαιτεί γνωστό checksum, χωρίς σιωπηρή παράκαμψη.
- Το `server.py` χρησιμοποιεί ιδιωτικό Playwright `_impl._driver`. Δεν
  χρειαζόμαστε server mode για το τοπικό Mini ERP· προτιμάται το async API.
- Υπάρχουν προεπιλεγμένα addons και πρόσθετες λήψεις μοντέλων/επεκτάσεων.
  Πριν την πιλοτική λειτουργία πρέπει να καθοριστούν ρητά οι απαραίτητες λήψεις,
  ώστε αποτυχία εγκατάστασης Camoufox να μην εμποδίζει την εκκίνηση του ERP.

Πρόταση σε τρία ανεξάρτητα βήματα προς απόφαση χρήστη:
(1) προαιρετική πιλοτική επιλογή για εκκρεμή PDF,
(2) ανεξάρτητη εγκατάσταση με fixed versions/hash και χωριστά profiles,
(3) σύντομη διάγνωση ανά παραστατικό με browser/αποτέλεσμα/αιτία αποτυχίας,
χωρίς credentials ή ολόκληρους συνδέσμους που περιέχουν tokens.
Δεν προτείνεται καθολικό αυτόματο retry πριν μετρηθεί όφελος σε πραγματικούς
παρόχους. Οι προτάσεις δεν έχουν ακόμη υλοποιηθεί.

Τοπική αναφορά ελέγχου:
`.local/verification/20261023T080035Z-4cab0a28/report.json`.
Συγκρίσεις παραδοτέων:
`.local/review/previous-deliverables.json` και `.local/review/deliverable-diffs.json`.


## Υλοποίηση μετά τις επιλογές χρήστη — 23/10/2026

Ο χρήστης ενέκρινε προαιρετικό Camoufox, εγκατάσταση μέσα στον φάκελο εφαρμογής
από Ρυθμίσεις και μικρό εξαγώγιμο crashlog αντί τεχνικών ενδείξεων ανά εγγραφή.
Υλοποιήθηκαν κεντρικές Ρυθμίσεις με Συνδέσεις, PDF/λήψεις και Υποστήριξη.

Η επίσημη wheel 0.5.8 ελέγχθηκε έναντι του SHA-256 της PyPI. Σε αντίθεση με το
snapshot main 0.5.7 του συνημμένου, το δικό της browser-pin.json ορίζει ακριβώς
`v156.0.1-beta.36`. Αυτό το ζεύγος επιλέχθηκε, μαζί με Playwright 1.62.0.
Ο Windows x64 browser ελέγχεται με το δημοσιευμένο SHA-256 της συγκεκριμένης
release. Ο installer τον δοκιμάζει με about:blank πριν γράψει ready marker.
Δεν κατεβάσαμε το Windows binary εδώ, ούτε εκτελέσαμε πραγματικό Camoufox.

Η ανάκτηση τρέχει σε χωριστή virtualenv/process μέσα στο Optional/Camoufox,
μόνο για επιλεγμένα εκκρεμή MARK. Επαναχρησιμοποιεί τους υπάρχοντες ελέγχους
αρχικού PDF και την εταιρική αντιστοίχιση/αρχειοθέτηση. Δεν εκτελεί HTML printing
σε Firefox. Τα profiles είναι χωριστά ανά εταιρεία/περιβάλλον/browser.
Το ZIP περιέχει τις οδηγίες και τον installer, όχι τα 1,31 GB του browser.

Το crashlog δεν κρατά exception message, locals, source lines ή αυθαίρετα paths,
και εξάγεται μόνο από τον χρήστη. Διατηρεί περιορισμένο ιστορικό αρχείων. Το
προϋπάρχον startup log του launcher είναι χωριστό και δεν εξάγεται από αυτήν
την επιλογή. Δεν αλλάξαμε λογιστική λογική, migrations ή σειρά ενεργειών RPA.
